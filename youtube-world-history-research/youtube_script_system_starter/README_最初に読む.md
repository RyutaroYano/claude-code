# Obsidian × Cursor で YouTube 台本を作るスターターセット

このフォルダは、**Obsidian を資料置き場**、**Cursor を読み込み・整理・執筆担当**として使うための雛形です。

## まず最初に理解すること
- この運用は、**同じ 1 つのフォルダ**を Obsidian と Cursor の両方で開いて使います。
- つまり「連携」とは、特別なプラグインではなく、**同じ作業フォルダを両方で見ること**です。
- Obsidian では資料を読む・書く・整理する。
- Cursor では資料を読ませて、要約・比較・プロット作成・台本作成をさせる。
- 人間は「目的を決める」「良し悪しを判断する」「各ブロックを直す」担当です。

## このフォルダの使い方
1. このフォルダを丸ごと 1 つ作業場所に置く。
2. Obsidian でこのフォルダを開く。
3. Cursor でもこのフォルダを開く。
4. `AGENTS.md` を消さずに使う。
5. まずは `01_視聴者理解`、`02_成功失敗の定義`、`03_過去台本データ`、`04_競合データ` に資料を入れる。
6. 新しい案件が来たら `06_案件進行中` のテンプレートフォルダを複製して案件名に変える。
7. Cursor に `00_案件ブリーフ.md` と `01_前提整理.md` を中心に読ませる。
8. いきなり全文台本を書かせず、**必ずプロット → ブロックごと執筆**で進める。

## 最初の 10 分でやること
### 1. まず資料を入れる場所
- `01_視聴者理解`  
  視聴理解の壁打ち結果、視聴者レポート、コメント要約など
- `02_成功失敗の定義`  
  成功の定義、失敗の定義、チェックリスト
- `03_過去台本データ`  
  成功台本、失敗台本
- `04_競合データ`  
  競合チャンネルの分析メモ
- `05_プロット設計`  
  プロット作成用の指示メモ
- `06_案件進行中`  
  いま作っている案件専用フォルダ

### 2. 何を先に作るか
最初に作るべきなのは完成台本ではありません。順番はこれです。

1. 視聴者理解をまとめる
2. 成功と失敗の定義を決める
3. 過去台本を整理する
4. 競合から学ぶべき構造を抜く
5. 今回案件の前提整理を作る
6. プロット案を作る
7. 採用プロットを決める
8. ブロックごとに台本を書く

## 一番大事なルール
- **生データは保管用、前提整理は実務用**です。
- 最初の整理だけは「全部 Cursor に渡す」で OK。
- ただし、毎回の執筆で毎回全部読ませるのは非効率です。
- 最高品質にしたいなら、  
  **生データ → 前提整理 → プロット → ブロック執筆**  
  の順に、情報をだんだん細くしていきます。

## おすすめ運用
### フェーズ 1: 知識をためる
- 成功台本を 10 本以上
- 失敗台本を 10 本以上
- 競合分析を 5 本以上
- 視聴者理解メモを 1 つ以上

### フェーズ 2: 実務用メモを作る
Cursor に次のように頼みます。

> このプロジェクト内の視聴者理解、成功台本、失敗台本、競合データを読み、
> 今後の執筆で使う前提整理を `06_案件進行中/案件名/01_前提整理.md` に作ってください。
> 内容は、視聴者像、刺さる悩み、避けるべき訴求、成功パターン、失敗パターン、競合から学ぶべき点に分けてください。

### フェーズ 3: プロットを作る
`00_案件ブリーフ.md` と `01_前提整理.md` を見ながら、3 案作らせます。

### フェーズ 4: 採用プロットを詳細化する
選んだ 1 案だけを深掘りし、ブロック構成を固定します。

### フェーズ 5: 台本をブロックごとに書かせる
1 ブロックずつ書かせます。人間が直したら、その修正を正解として次に進みます。

## いきなり全文を書かせてはいけない理由
- 途中で構造ミスに気づいても直しにくい
- フックと中盤の温度差が出やすい
- 人間の修正意図が後半に反映されにくい
- 成功/失敗の定義が後半で崩れやすい

## ブロック執筆の基本型
長尺動画なら、まずはこの 6 ブロックで十分です。

1. フック
2. 問題提起
3. 原因の言語化
4. 解決策 1
5. 解決策 2 / 具体例
6. 締め / CTA

## 人間が直すときの原則
- 直すのは「言い回し」だけではなく「狙い」も直す
- 直した理由を `10_人間修正メモ.md` に 1 行でも残す
- 次に Cursor に「この修正を正解として反映して」と伝える
- うまくいった修正は次回からルール化して `AGENTS.md` に追加する

## 慣れてきたらやること
- `.cursor/commands` を使って毎回の指示を定型化する
- `02_成功失敗の定義/02_評価基準チェックリスト.md` を育てる
- 本当に要らない重いファイルは `.cursorignore` で除外する

## 迷ったらこれだけ覚える
- Obsidian = 保管・整理・手修正
- Cursor = 読み込み・比較・提案・執筆
- 人間 = 目的設定・選択・最終判断
- 進め方 = 生データ → 前提整理 → プロット → ブロック執筆
